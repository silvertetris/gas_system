# 09. PINN — 히터 열전달식을 포함한 물리층

작성 2026-09-13 (§8 에서 개정됨 — 먼저 §8 을 읽어라). 코드는 `pinn/test/`. 결과 `pinn/test/output/metrics.csv`, 그림 `pinn_{M,Z}.png`.

---

## 1. 무엇이 달라졌나

1차 파일럿에는 **히터 물리가 통째로 없었다.** 신경망이 헤더온도 `T_hdr` 을 그냥 예측하고,
배관 구간(`Q5` 줄-톰슨 + `Q6` 지중 열교환)만 물리식이었다. `m·c_p·ΔT` 도 `U·A·ΔT_lm` 도
들어 있지 않았다 — 즉 **열전달식이 없었다.**

이번에 (Q2)·(Q3)·(Q4) 를 물리층에 넣어 연쇄를 닫았다.

```
(Q2) 열교환      m_u·c_p·(T_out,u − T_in) = U_u·A_u·ΔT_lm,u
     ⇔ ε-NTU     NTU_u = U_u·A_u/(m_u·c_p),   ε_u = 1 − exp(−NTU_u)
(Q3) 출구온도    T_out,u = T_in + ε_u·(T_bath,u − T_in)
(Q4) 합류점      T_hdr   = Σ_u f_u·T_out,u + β·T_in          f_u = m_u/M, β = m_byp/M
(Q5) 줄-톰슨     T_reg   = T_hdr − μ_JT·ΔP
(Q6) 매설배관    T_61    = T_g + (T_reg − T_g)·exp(−N),  T_g = a + b·T_in
(Q1) 수조열수지  C_eff·dT_bath/dt = fire·s·Q_버너 − m·c_p·ΔT − Q_loss·(T_bath−T_in)/Δref
```

`Q1` 은 구현했으나 **기각**했다(§4).

## 2. LMTD 식은 왜 따로 없나 — 같은 식이다

수조는 열용량이 커서 관 길이방향 온도가 일정하다(단일유체 열교환기). 그 조건에서

```
ΔT_lm = [(T_b−T_in) − (T_b−T_out)] / ln[(T_b−T_in)/(T_b−T_out)]

(T_out − T_in)/ΔT_lm = ln[(T_b−T_in)/(T_b−T_out)] = −ln(1−ε) = NTU = U·A/(m·c_p)
```

이건 근사가 아니라 **대수적 항등식**이다. 실측으로 확인했다(`regime=flow` 구간):

| 히터 | n | `ΔT/ΔT_lm` 중앙 | `−ln(1−ε)` 중앙 | 최대 상대오차 |
|---|---|---|---|---|
| A | 2,615,931 | 0.387877 | 0.387877 | 1.4e-15 |
| B | 2,182,214 | 0.432973 | 0.432973 | 1.4e-15 |
| O | 996,328 | 0.382960 | 0.382960 | 1.4e-15 |
| P | 2,880,524 | 0.517343 | 0.517343 | 1.6e-15 |

부동소수점 한계까지 동일하다. **LMTD 형태를 추가해도 얻는 정보가 0**이므로 ε-NTU 로만 쓴다.

## 3. 유량은 왜 식별되나 — 문서 07 §4 정정

구 판은 `NTU = U·A/(m·c_p)` 에서 둘이 곱으로만 나타나 미식별이라고 적었다. **틀렸다.**
`U` 는 `m` 과 독립이 아니다(제작도서 직렬저항, 부하표 대조 −0.1%):

```
1/U(x) = 1/(α_io·x^0.8) + 1/α_o + R_f          x = m/m_d
1/NTU ∝ x^0.2/α_io + x/α_o + x·R_f             ← x 의 멱이 달라 곱으로 축약 안 됨
```

| x=m/m_d | 0.1 | 0.25 | 0.5 | 1.0 | 2.0 | 3.0 | 5.0 |
|---|---|---|---|---|---|---|---|
| U/U(설계) | 0.429 | 0.662 | 0.843 | 1.000 | 1.120 | 1.172 | 1.222 |
| **NTU** | 1.740 | 1.075 | 0.684 | **0.406** | 0.227 | 0.158 | 0.099 |
| (상수U 가정) | 4.056 | 1.622 | 0.811 | 0.406 | 0.203 | 0.135 | 0.081 |

치역 0.026~3.13 전구간 단조감소 → 유일 역산. `prex_multi/config.py:regime_thresholds` 는
**상수U 가정**을 쓰고 있어 저유량에서 1.5배 어긋난다(향후 정정 대상).

### 3-1. 그런데 순방향 역산은 검증 실패다

제작도서 상수를 **고정**하고 690만행(2013-06~2026-08)을 역산했다:
A x중앙 0.61 · B 0.24 · O 0.12 · P 1.09. 숫자는 나온다. 독립 검증 결과:

| 검증 | 기대 | 결과 |
|---|---|---|
| β vs 밸브개도 Spearman (유량가중 vs `max()` 근사) | 유량가중이 더 높아야 | M 0.827 vs **0.866** / Z 0.836 vs **0.840** |
| 계절성 겨울/여름 (M = 인천도시가스) | **> 1** | 중앙비 **0.86**, 평균비 0.74 |
| Spearman(m_total, T_in) | **음수** | M **+0.052** / Z **+0.151** |

**방향이 틀렸다.** 그래서 PINN 에서는 `U·A` 보정계수 `ua_log[u]` 를 학습 모수로 두고,
`Q4`(실측 `T_hdr`)로 배분을, 실측 β 정합으로 혼합비를 묶는다.

## 4. 🔴 (Q1) 수조 열수지 — 기각

`Q1` 은 절대 유량 스케일을 묶는 **유일한** 식이다. 그런데 데이터가 모순이다.
통가스 시간대(`flow` 비율 > 0.8)의 시간평균:

| 히터 | 버너 duty 평균 | 버너열 `q_fire` | ε 역산 흡수열 `q_gas` | 수조 저장항 | 손실 | 필요 `fire` |
|---|---|---|---|---|---|---|
| A | 0.036 | 36 kW | **127 kW** | −5 kW | 5.5 kW | 0.59 |
| B | 0.084 | 84 kW | **124 kW** | −4.5 kW | 4.7 kW | 0.37 |
| O | 0.145 | 144 kW | **644 kW** | −20 kW | 30 kW | 0.34 |
| P | 0.244 | 243 kW | **507 kW** | −7 kW | 25 kW | 1.57 |

`q_fire` 중앙값은 A·B·O 에서 **0** 이다(통가스 중인데 버너가 절반 이상의 시간 꺼져 있다).
흡수열이 버너 발열의 **3~4배**이고 수조 저장항으로도 못 메운다. 문서 07 §2 의
"수조 열수지가 설계 `U·A` 대비 2~5배 작다"는 벽과 **같은 것**이다.

절제실험 (같은 분할·시드, LR 1e-3):

| 조합 | AUC (M/Z) | 리프트1% (M/Z) | (Q4) 헤더 RMSE (M/Z) |
|---|---|---|---|
| Q1 포함 `fire≤1.0` | 0.800 / 0.905 | 17.8 / 17.0 | 9.00 / 3.33 |
| **Q1 제외** | **0.825 / 0.908** | 16.8 / 22.7 | **5.98 / 3.21** |
| Q1 포함 `fire≤3.0` | 0.663 / 0.867 | 1.5 / 24.1 | 13.61 / 3.23 |

→ `W_Q1 = 0`. 코드는 남겨 둔다(`model.bath_balance`) — 유량 계측이 생기면 바로 쓴다.

### 5-1. (Q4) 는 시간평균 해상도에서 완전히 만족될 수 없다

`T_hdr = Σf·T_out + β·T_in` 은 가중합이므로 `T_hdr` 이 `{T_out,u, T_in}` 의 **볼록껍질**
안에 있어야 한다. 시간평균 행에서:

| 계열 | 껍질 안 | 밖일 때 이탈 중앙 / p90 |
|---|---|---|
| M | 83.1% | 0.94 / 2.87 ℃ |
| Z | 69.0% | 2.19 / 5.59 ℃ |

→ **(Q4) RMSE 에 하한이 있다.** 센서 오프셋 + 시간평균의 Jensen 오차 + 분(分) 단위
regime 혼재가 원인이다. 모델 탓이 아니다.

## 7. 한계

1. **`m·c_p` 와 `U·A` 를 따로 못 본다.** 물리층에 들어간 것은 그 **비(NTU)** 다.
   빙결 예측에는 그걸로 충분하다(출구온도를 정하는 건 비다). **열화 추적은 여전히 불가** —
   그건 `U·A` 자체를 봐야 하고 절대 유량이 필요하다(문서 07 §2, §3).
2. **`c_p = 2739.8 J/kg·K` 는 조건 미기재.** 제작도서 설계값이고 온도·압력 조건이 적혀
   있지 않다. 가스 조성 태그(`AI*`)는 전부 DEAD(가상/SW)라 실제 조성으로 재계산할 수 없다.
   M(0.8 MPa)과 Z(2.6 MPa)는 압력대가 달라 `c_p`·`μ_JT` 가 실제로 다를 것이다 —
   **두 계열의 μ_JT 가 다르게 나오는 것은 오류가 아니라 물리적으로 맞다.**
3. **사건률 드리프트**: 훈련 34.9%/20.6% → 시험 3.26%/1.33%. 캘리브레이션이 과대예측으로
   기운다(등장성 보정 후에도). 운영 임계는 문서 08 §6 을 쓴다.
4. **파일럿 범위**: 2012~2016, 1시간 격자, 지평 6h. 전 구간(2011~2026, 1분)으로 확장 필요.
5. `regime_thresholds` 의 상수U 가정(§3) 정정 시 `flow`/`isolated`/`lowflow` 경계가 바뀐다 —
   문서 03 의 T1~T4 검증을 다시 돌려야 한다.

## 8. 🔴 개정 (2026-09-13) — ε-NTU 역산을 뺐다

문서 10 의 검정 결과 **ε-NTU 유량 역산은 부호가 반대**였다. §1~§7 의 `U·A` 보정·유량 역산은
**폐기**하고 `ε` 을 관측값 그대로 쓰는 구조로 바꿨다.

| | 개정 전 (§1~§7) | 개정 후 |
|---|---|---|
| `ε` | `x_u` → `NTU(x)` → `ε` **역산** | **관측값** — 신경망이 예측, 지도 가능 |
| 혼합 가중 | `m_u` from 역산 (부호 반대 ❌) | `w_u ∝ m_설계,u·ε_u` (문서 10 §3) |
| `β` | 자유 헤드 → 0.05 로 붕괴 | **밸브개도 단조맵** (독립 센서) |
| `ua_log`·`fire` | 학습 모수, ×13.9 로 튐 | **제거** |
| 타깃 정렬 | 상태마다 독립 극값 | **최저 공급온도가 난 그 시각**으로 전부 정렬 |
| (Q3) 잔차 | 손실에 있었음 | **제거 — 항등적으로 0** (ε 정의와 같다) |

`ε` 을 관측으로 쓰면 `U·A`·`m` 분해는 포기하지만 **(Q3)·(Q4) 의 모든 입력이 관측 가능**해져
전부 지도 학습된다: `ε_u`·`T_bath,u`·`T_in`·`valve`·`ΔP`.
