# KF-PINN 상태공간 설계 — HTR-31P

> 작성: 2026-09-11. `m_gas`를 밸브식 역산(`gas_flow_proxy`)에서 **잠재변수**로 옮기는 설계 변경.
> 배경: P&ID 판독으로 역산의 전제가 반증됐다 (`htr31p_flow.md` §7-2·§7-3).
> 물리식 원형: `data/docs/06_물리식_출처정리.md` §2(H1/H2), 계수는 제작도서 OCR §5(T1).

---

## 1. 왜 바꾸나 — 한 문단

기존 설계는 정압기 밸브식으로 `m_gas`를 역산해 H2식에 넣었다. 그런데 P&ID상
**히터 2대 출구가 공통헤더로 합류한 뒤 정압기 4라인이 각자 뽑아 가므로** `PCV-41P` 통과유량은
`HTR-31P` 통과유량이 아니고, `P_out`으로 쓰던 `PI43O`마저 옆 라인(41O) 전용값이었다.
즉 역산의 **재료(`PI43O`)와 논리(직렬 질량보존)가 둘 다** 무너졌다.
→ `m_gas`를 관측값으로 "넣지" 말고, 물리식과 함께 **추정**한다.

---

## 2. 대체 관측식 — ε-NTU (신뢰 태그 3개만 쓴다)

튜브번들을 "수조온도 `T_bath`의 열원에 대한 열교환기"로 보면:

```
ε   = (T_out − T_in) / (T_bath − T_in)          ← TI33P, TI21Z, TI-D2P 만으로 매 분 계산
NTU = −ln(1 − ε) = U·A / (m_gas · c_p)
```

**이 식에는 `PI43O`·`ZI41P`·`Cv`·밸브특성곡선이 하나도 안 들어간다.** P&ID로 흔들린 재료를
전부 우회하고 T1 등급 태그 3개만 쓴다. 구현: `prex/trend.py::add_heat_exchange()` →
컬럼 `htx_eps`, `htx_ntu`, `htx_drive_c`.

실측(2026-09-11 재실행, 유효 5,021,531행 = 64.3%; 조건 `T_bath − T_in > 15℃`):

| 구간 | n | ε p25/p50/p75 | NTU p50 |
|---|---|---|---|
| 전체 | 5,021,531 | 0.073 / 0.244 / 0.550 | 0.280 |
| 버너 ON | 860,486 | 0.358 / 0.536 / 0.700 | 0.767 |
| 버너 OFF | 4,161,045 | 0.059 / 0.185 / 0.472 | 0.204 |

NTU가 0.2~1.2 범위로 물리적으로 타당하다(설계점 NTU = U·A/(m·c_p) = 16,188/(14.57×2,739.8) = 0.41).

## 3. 식별성 — 무엇이 분리되고 무엇이 안 되나

**ε 한 식으로는 `U·A`와 `m_gas`를 분리할 수 없다.** NTU는 둘의 *비*이기 때문이다(구조적 미식별).
분리하려면 두 번째 식, 즉 버너 OFF 구간의 수조 열수지가 필요하다:

```
−M_w·c_w · dT_bath/dt = m_gas·c_p·(T_out − T_in) + Q_loss     … 기울기=m_gas, 절편=Q_loss
U·A = NTU · m_gas · c_p
```

`prex/identify_mgas.py`로 실행해 봤고, **결과는 신뢰할 수 없다**:

| | pooled 추정 | 설계값 | 비 |
|---|---|---|---|
| `m_gas` | 1.24 kg/s | 14.57 kg/s | **0.09배** |
| `U·A` | 0.95 kW/K | 16.2 kW/K | **0.06배** |
| `Q_loss` | 111.1 kW | — | 설계열량의 11% (과대) |
| R² | 0.379 | — | 약함 |

**원인 분해**:

1. **저부하 열전달 저하 — 실재하나 부족하다.** 가스측 α ∝ m^0.8(Dittus-Boelter)이고 설계점
   저항 비중은 가스측 30% / 수조측 70%다. m/m_design = 0.085까지 떨어져도 U·A는 16.2 → 6.75 kW/K,
   즉 **2.4배**밖에 안 준다. 관측된 16배 괴리를 설명 못 한다.
2. **진공식 잠열항 — 이게 주범이다.** HTR-31P는 **감압비등식**이라 수조가 비등·응축하면
   유효 열용량이 현열값 `M_w·c_w`(60.76 MJ/K)보다 훨씬 커진다. 그러면 `dT_bath/dt`가 그만큼
   작게 관측되고, 위 회귀의 **기울기와 절편이 같은 미지 배율로 함께 나눠진다** →
   `m_gas`와 `Q_loss`가 동시에 과소 추정된다. 실제로 둘 다 ~0.1배로 어긋나 있어 이 설명과 맞는다.

> **결론**: plug-in 추정은 포기한다. `m_gas`뿐 아니라 **수조 유효 열용량(잠열 배율)도 미지**로 두고,
> 물리식·관측을 동시에 만족시키는 값을 **필터로 공동추정**한다. 이것이 잠재변수 설계의 근거다.

## 4. 상태공간 정식화

**상태 x(t)** (괄호 = 초기값/prior 출처)

| # | 기호 | 의미 | 단위 | 성격 |
|---|---|---|---|---|
| x₁ | `T_bath` | 수조(열매체) 온도 | ℃ | 관측됨 |
| x₂ | `T_out` | 히터 출구 가스온도 | ℃ | 관측됨 |
| x₃ | `ln m_gas` | **가스 질량유량** | ln(kg/s) | **잠재** — random walk(분 단위 느림). prior: 설계 14.57 kg/s |
| x₄ | `ln UA_ref` | **기준부하 환산 전열계수** | ln(W/K) | **잠재** — 아주 느린 random walk. **이것의 하락 = 열화지표** |
| x₅ | `Q_burner` | 버너 열출력 | W | **잠재** — `H31POH` 게이트. prior: 0.996 MW |
| x₆ | `ln k_lat` | 수조 **유효 열용량 배율**(잠열) | — | **잠재** — 진공압 regime 의존. prior 1.0 |

로그를 쓰는 이유: 양수 제약과 곱셈 구조(NTU가 비율)를 선형화하기 좋아서다.

**물리식 (PINN residual)**

```
(H1)  k_lat·M_w·c_w · dT_bath/dt = s(t)·Q_burner − Q_gas − Q_loss
(H2)  Q_gas = m_gas · c_p · (T_out − T_in)
(H3)  T_out = T_in + ε·(T_bath − T_in),   ε = 1 − exp(−U·A/(m_gas·c_p))
(H4)  U·A = UA_ref · (m_gas / m_design)^0.8          ← 부하보정. 열화는 UA_ref 에만 들어간다
```

(H4)가 핵심이다. **이걸 안 넣으면 "열화지표"가 그냥 부하를 따라다닌다** — §3의 1번 때문이다.

## 8. 남은 위험

- **x₄(UA_ref)와 x₆(k_lat)이 서로 흡수할 수 있다** — 둘 다 느린 잠재변수라 구분이 약하다.
  `k_lat`을 `PI-D2P_norm`의 함수로 **묶어(parametrize)** 자유도를 줄이는 것이 안전하다.
- (H4)의 지수 0.8은 **교과서값**이다(T3 수준). 데이터로 재추정하되 좁은 prior를 둘 것.
- `H31POH`가 단순 ON/OFF인데 실제 버너는 **BLOWER 회전수로 연속 변조**된다(문서 05 §3-3).
  `Q_burner`를 게이트×상수로 두면 이 변조가 x₅ 잡음으로 들어간다.
